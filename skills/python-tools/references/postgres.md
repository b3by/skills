# PostgreSQL

PostgreSQL through SQLAlchemy 2 and the psycopg 3 driver, with Alembic
migrations.

```bash
uv add 'sqlalchemy>=2.1,<3' 'psycopg>=3.3,<4'   # library
uv add 'psycopg[binary]>=3.3,<4' alembic        # application or service
```

Libraries depend on plain `psycopg` and let the application choose how the
driver is installed. Use the `postgresql+psycopg://` URL scheme, which
selects psycopg 3 for both sync and `asyncio` engines.

## Models

```python
import datetime

from sqlalchemy import BigInteger
from sqlalchemy import DateTime
from sqlalchemy import Identity
from sqlalchemy import MetaData
from sqlalchemy import String
from sqlalchemy import func
from sqlalchemy.orm import DeclarativeBase
from sqlalchemy.orm import Mapped
from sqlalchemy.orm import mapped_column


NAMING_CONVENTION = {
    'ix': 'ix_%(column_0_label)s',
    'uq': 'uq_%(table_name)s_%(column_0_name)s',
    'ck': 'ck_%(table_name)s_%(constraint_name)s',
    'fk': 'fk_%(table_name)s_%(column_0_name)s_%(referred_table_name)s',
    'pk': 'pk_%(table_name)s',
}


class Base(DeclarativeBase):
    """Base class of every table."""

    metadata = MetaData(naming_convention=NAMING_CONVENTION)
    type_annotation_map = {
        datetime.datetime: DateTime(timezone=True),
    }


class RecordRow(Base):
    """A stored record."""

    __tablename__ = 'records'

    id: Mapped[int] = mapped_column(BigInteger, Identity(), primary_key=True)
    name: Mapped[str] = mapped_column(String(64), unique=True)
    size: Mapped[int] = mapped_column(default=0)
    note: Mapped[str | None]
    created_at: Mapped[datetime.datetime] = mapped_column(
        server_default=func.now()
    )
```

- Set a constraint naming convention on the metadata, so Alembic can find
  and drop constraints by name.
- Use `Mapped[...]` annotations everywhere. `Mapped[str | None]` makes the
  column nullable, `Mapped[str]` makes it `NOT NULL`.
- Use `BigInteger` identity primary keys, or `uuid.UUID` keys when ids are
  exposed or generated outside the database.
- Store times as `timestamptz` (the `type_annotation_map` above) and only
  timezone-aware `datetime` values, in UTC.
- Use `JSONB` (from `sqlalchemy.dialects.postgresql`) for semi-structured
  data, and real columns for anything you filter or join on.
- Name tables in plural `snake_case`, and name row classes with a `Row`
  suffix to keep them apart from pydantic models.

## Engine and sessions

```python
def make_session_factory(url: str) -> sessionmaker[Session]:
    engine = create_engine(url, pool_pre_ping=True)

    return sessionmaker(engine, expire_on_commit=False)


def find_record(session: Session, name: str) -> RecordRow | None:
    query = select(RecordRow).where(RecordRow.name == name)

    return session.scalars(query).one_or_none()


with factory.begin() as session:  # commits on success, rolls back on error
    row = find_record(session, 'alpha')
```

- Create one engine per process at startup, read its URL from the settings
  (see [pydantic.md](pydantic.md)), and `dispose()` it at shutdown. Never
  create engines per request or at import time.
- Use one session and one transaction per unit of work (a request, a job, a
  message), with `factory.begin()`. Don't share a session across threads or
  tasks.
- Write queries in 2.0 style (`select()`, `insert()`, `update()`,
  `session.scalars()`, `session.execute()`). Don't use the legacy
  `session.query()`.
- When raw SQL is needed, use `text()` with bound parameters
  (`text('select * from records where name = :name')`). Never build SQL with
  f-strings or concatenation.
- Load relationships explicitly (`selectinload`, `joinedload`) instead of
  relying on lazy loading in loops.
- For `asyncio` services, use `create_async_engine` and `AsyncSession` with
  the same URL scheme, and `async_sessionmaker`.

## Migrations (Alembic)

```bash
uv run alembic init --template pyproject migrations
uv run alembic revision --autogenerate -m 'add records table'
uv run alembic upgrade head
uv run alembic downgrade -1
```

- In `migrations/env.py`, set `target_metadata = Base.metadata` and take the
  URL from the settings instead of `alembic.ini`:

  ```python
  url = get_settings().database_url.get_secret_value()
  config.set_main_option('sqlalchemy.url', url.replace('%', '%%'))
  ```

  Remove the placeholder `sqlalchemy.url` from `alembic.ini`.
- Make Alembic run ruff on every new revision, so generated files follow the
  project style. Add to `pyproject.toml`:

  ```toml
  [[tool.alembic.post_write_hooks]]
  name = "ruff_check"
  type = "module"
  module = "ruff"
  options = "check --fix REVISION_SCRIPT_FILENAME"

  [[tool.alembic.post_write_hooks]]
  name = "ruff_format"
  type = "module"
  module = "ruff"
  options = "format REVISION_SCRIPT_FILENAME"
  ```
- Always review an autogenerated migration before committing it. Autogenerate
  misses renames (it sees a drop and an add) and some type and constraint
  changes.
- Write a working `downgrade()` unless the change can't be undone, and say
  so in the migration when it can't.
- Never edit a migration that has been applied outside your machine. Add a
  new one.
- Run migrations as a deployment step, never on application import or
  startup in multi-instance services.
- Separate data migrations from schema migrations, and keep them working
  without importing the application's current models.

## Tests

Test against a real PostgreSQL server, never SQLite: types, constraints and
SQL behaviour differ. In projects that use the
[`python-containers`](../../python-containers/SKILL.md) setup, use its
Compose `postgres` service and run the tests in the container. Otherwise,
locally:

```bash
docker run --rm -d --name my-package-db -p 5432:5432 \
  -e POSTGRES_PASSWORD=postgres postgres:18.6-trixie
export MY_APP_DATABASE_URL=postgresql+psycopg://postgres:postgres@localhost:5432/postgres
uv run alembic upgrade head
uv run pytest -m postgres
```

In CI, add a service to the job in the CI workflow:

```yaml
    services:
      postgres:
        image: postgres:18.6-trixie
        env:
          POSTGRES_PASSWORD: postgres
        ports: ['5432:5432']
        options: >-
          --health-cmd pg_isready --health-interval 5s
          --health-timeout 5s --health-retries 10
    env:
      MY_APP_DATABASE_URL: postgresql+psycopg://postgres:postgres@localhost:5432/postgres
```

- Mark database tests with `@pytest.mark.postgres`.
- Build the schema once per session by running the migrations, so tests also
  check that the migrations work.
- Isolate each test in a transaction that is rolled back at the end:

  ```python
  @pytest.fixture
  def session(engine):
      with engine.connect() as connection:
          transaction = connection.begin()
          session = Session(
              bind=connection,
              join_transaction_mode='create_savepoint',
          )

          yield session

          session.close()
          transaction.rollback()
  ```

- These credentials are for disposable local and CI databases only. Never
  reuse them anywhere else.
